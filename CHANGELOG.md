## [1.6.2] - 2026-09-29

### Changed — trait lookup values corrected

Trait values fetched from online databases were wrong in several cases. Lookups made with 1.6.1 or earlier may
differ from 1.6.2 results.

- **WoRMS body sizes:**
  - Sizes now use each record's own unit. A 20 cm mussel was recorded as 2 cm, so it moves from MS3 to MS5.
  - Weight records in kg are no longer read as lengths.
  - Sizes written without a space ("5mm") are recognised.
- **FishBase weights** stay in grams. Cod was recorded as 96 t.
- **Name lookup:**
  - Scientific names are looked up as given before any singular form is tried, so "Pollachius virens" now
    resolves.
  - For common names, an exact match wins. Several possible matches give lower confidence and a warning.
- **Batch lookups:**
  - A species whose lookup fails becomes an error row with a warning, instead of stopping the whole Trait
    Research batch.
  - Failed rows are not sent to Food Web Construction, and the transfer message says how many were skipped.
- **Ecopath import functional groups:**
  - WoRMS classifications now count as medium confidence. Groups whose names give no specific hint get their
    WoRMS group; for example *Limecola*, *Saduria*, *Marenzelleria*, *Eurytemora* and *Bosmina* no longer fall
    back to "Fish".
  - A specific group name still wins over WoRMS, so "Mysids" stays Zooplankton; "Krill" and *Euphausia* are
    also Zooplankton.
  - Body mass from an ambiguous FishBase match is no longer stored.
- **Habitat:** buried (infaunal) bivalves are classified as EP4 before the depth rule is applied.

### Notes

- Cached lookups (`cache/taxonomy/`) from 1.6.1 or earlier are refreshed automatically on first use.
- No offline trait database rebuild is needed.

### Fixed

- **traits:** C-6a trait lookups - WoRMS units, FishBase grams, name resolution, no batch abort (#19) (6c0c4e9)

## [1.6.0] - 2026-09-29

### Changed — trait codes changed

All trait codes now come from one vocabulary, the one the food-web model uses. Trait tables, offline-DB rows
and trait-based networks exported from 1.5.x or earlier are **not comparable** with 1.6.0 output.

- **Mobility (MB) codes have new meanings.** MB1 Sessile; MB2 Passive floater / drifter (plankton, medusae);
  MB3 Crawler-burrower (includes infaunal burrowers); MB4 Facultative / limited swimmer; MB5 Obligate swimmer.
  Before, the same code meant different things in different places:
  - the live harmonizer used MB2 = burrower and MB3 = crawler;
  - the ontology path used MB3 = floater;
  - the local SpeciesEnriched table used MB2 = crawler;
  - the legend showed MB4 = burrower.
  "nekton" now only sets mobility (MB5); it no longer sets an EP.
- **Environmental position (EP):**
  - "benthopelagic" and "bathydemersal" are EP2. "benthopelagic" was EP1.
  - Zonation words (subtidal, sublittoral, intertidal, littoral) no longer set an EP; taxonomy or depth
    decides. Subtidal and intertidal were EP4.
  - BIOTIC burrowers are EP4. Attached, tube-dwelling and free-living taxa are EP3 (they were EP3/EP2).
  - "benthic surface" is EP3.
  - Bare "benthic" / "benthos" (for example the WoRMS functional group) sets no EP. Taxonomy and depth decide,
    so infaunal bivalves stay EP4.
  - Copepods, cladocerans, salps and medusae are pelagic (EP1), and this is decided before the depth rule.
    "ichthyoplankton" is EP1.
  - The default is EP3 (was EP2).
- **Protection (PR) and cnidarian mobility:**
  - Sea urchins, sea stars, brittle stars and crinoids are PR7. Sea cucumbers are PR1. All were PR5.
  - Bare "exoskeleton" is PR4. "heavy exoskeleton" and calcified exoskeletons are PR8.
  - "soft shell" is PR5.
  - Small arthropods are PR4. They were PR5 when the crustacean rule was off.
  - Scyphozoa and Cubozoa are MB2 and Anthozoa MB1. All cnidarians were MB1.
  - The "Cnidarians -> MB1" rule checkbox is retired.
- **PR1 (mucus / cuticle) is in the model and validates, as does PR4.** The PR1 row is a copy of the PR0 row.
- **New MS1 and MS6 columns** in the EP x MS and PR x MS matrices, copied from MS2 and MS5. Before, MS1/MS6 prey
  fell to a hard-coded 0.05 / 0.50. These columns and the PR1 row are placeholders until calibrated.
- **Sessile consumers recalibrated.** In the mobility matrix, a sessile (MB1) consumer's probability for mobile
  prey (MB2-MB5) is now 0.10 instead of 0.05. Suspension feeders therefore keep drifting plankton at the default
  threshold. This is a calibration placeholder, not a fitted value.
- **Strict link threshold.** A link now needs a probability strictly above the threshold. At the default 0.05,
  every pair sitting at the matrices' 0.05 "implausible" floor loses its link. Threshold 0 no longer links
  every pair, self-loops included.
- **Unknown or missing trait codes:**
  - An unknown trait code is now an error in the Food Web Construction tab, instead of a silent floor value.
  - A species with a missing trait code loses only the role that needs that code. Missing PR: it cannot be
    eaten. Missing FS: it cannot eat.
  - One warning per build names the affected species and their missing codes.

### Notes

- **Action required after upgrading: rebuild the offline trait database.** Use Trait Research > Rebuild
  Database as an unlocked admin, or run `Rscript scripts/initialization/build_offline_trait_db.R` from the app
  directory. Until then, the old database is skipped and lookups use the online sources. The Trait Research
  database panel shows "Rebuild required" meanwhile.
- Cached lookups (`cache/taxonomy/`) from 1.5.x are refreshed automatically on first use.
- Machine-learning gap filling no longer predicts MB until the models are retrained on the new codes.
- The confidence label bands (0.34 / 0.67) are unchanged in this release.

## [1.5.3] - 2026-09-28

### Notes

- **Action required: freshwaterecology.info API key.** The key that used to be hard-coded in `R/config.R`
  is removed. It remains in the public git history, so rotate it with the provider. Enter the new key through
  Trait Research > Configure API Keys; it is stored in the gitignored `config/api_keys.json`. Without a key,

  configured. App and console builds share the lock `cache/offline_traits.db.lock`. A build writes to

  are limited to http(s) and DOIs.

  is written with owner-only permissions (0600), and a failed save shows an error without ending the session.

## [1.5.0] - 2026-09-27

### Results changed

These fixes change numerical outputs. Results computed with earlier versions
on the paths listed below are not comparable and should be regenerated.

- **MTI / keystoneness - every source.** Formula replaced (Ulanowicz & Puccia
  1990 MTI, Libralato et al. 2006 keystoneness), with KS on the log10 scale as
  EwE reports it. Producers can now have positive impacts on their consumers.
  Statuses are Keystone / Dominant (top KS quartile, split at 5 % relative
  biomass), Other and Undefined ("Rare" is gone). Earlier KS values and
  statuses are not comparable. Keystoneness now requires a directed network.
- **Trophic levels changed for:**
  - CSV/Excel EwE imports (previously inverted; the Detritus group is now kept
    and functional-group heuristics shift);
  - the Kongsfjorden metaweb;
  - user metawebs built from the template or uploaded CSVs (previously
    inverted);
  - the bundled example datasets Simple_3Species and Caribbean_Reef
    (previously inverted);
  - per-hexagon meanTL/maxTL for **all** metawebs: the spatial tab now uses
    the same estimator as the Food Web tab (the old fixed 10-pass loop also
    counted unreachable nodes), and the direction is corrected for the
    inverted metawebs above;
  - Rpath TL after balancing (previously overwritten by a transposed
    recomputation).
- **Unchanged TL** (two errors cancelled): the Baltic, Barents (boreal and
  arctic) and North Sea bundled metawebs as shipped, `.ewemdb` imports and
  EcoBase imports. EcoBase MTI/KS still change (formula and diet proportions).
- Nodes with no path from a basal species now show TL `NA` (with a warning)
  instead of about 101.
- **Rpath biomass for groups with habitat area < 1.** EwE stores biomass per
  habitat area; the Rpath conversion now multiplies by the habitat-area
  fraction, as the network import always did. Rpath balancing of models with
  `Area < 1` (e.g. the Coastal and Mar Menor examples) changes. Network-tab
  biomasses are unchanged.
- Rpath conversion keeps cannibalism as entered (previously set to 0 without
  renormalising the predator's diet). One shared tolerance (1e-3) now drives
  both the diet-sum warning and the UI diet-validation panel, so EwE rounding
  residues no longer warn.
- Rpath diagnostics and the trophic pyramid now work on the balanced Rpath
  object (they always showed "unavailable" before), exclude detritus from
  "living" totals and report detritus separately.
- **Imported attributes:** metaweb exports now carry their real biomass, body
  mass, metabolic type, efficiency, P/B, Q/B and functional groups (previously
  defaults), and EwE diet proportions survive the metaweb round trip; EcoBase
  imports get metabolic types and functional-group body-mass estimates instead
  of `biomass x 100`; EwE `Type` now decides detritus and producer groups, and
  names such as "Detritivores" are no longer classed as detritus.
- EwE diet CSVs with unparseable cells (e.g. decimal commas) now warn, and a
  diet matrix with no links stops the import instead of "succeeding" with 0
  edges.
- **EMODnet habitat on EwE import** uses the sampling point you enter (the
  inputs are empty by default with world-wide limits; the Gdansk default is
  gone) and reloads the habitat layer when the point is outside it. Previously
  the step failed or silently used Gdansk Bay.

**Files you hold that must be fixed or regenerated:**
- exports (CSV, RDS, GraphML) from the "changed" paths above, including
  trait food-web RDS/GraphML exports (edges now run resource -> consumer) and
  the trait tab's adjacency-matrix CSV (now rows = prey);
- metawebs exported from Metaweb Manager before this release that were derived
  from an EwE import or are copies of the four bundled metawebs: their
  `predator_id` / `prey_id` columns are swapped - swap them back
  (`scripts/initialization/fix_metaweb_orientation.R` shows how) or re-derive
  them;
- adjacency-matrix CSVs prepared from the old upload help ("row species eats
  column species"): the format is rows = prey, columns = predators - transpose
  old files.

**Known issue:** the Basic-Estimates CSV/Excel import may read "Biomass in
habitat area" instead of total biomass for groups with habitat area < 1; use
the native `.ewemdb` import for such models until this is fixed.
