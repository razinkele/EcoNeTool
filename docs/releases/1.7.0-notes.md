### Added — Network Comparison tab

A new sidebar entry, **Network Comparison**, places two food webs side by side: before and after a change, two
regions, or an ECOPATH model against a trait-built web.

- **Two snapshot slots.** Store the currently loaded web as Network A or Network B, or load one of the bundled
  example webs straight into a slot. Slots keep their copy for the session, so importing the second web never
  overwrites the first.
- **What is compared.** Topological indicators (S, C, G, V, mean shortest path, mean trophic level, omnivory)
  side by side with the difference B − A, plus the biomass-weighted indicators when both webs carry biomass;
  species shared, only in A and only in B with a Jaccard similarity; trophic links among the shared species
  (prey → predator) shared, only in A and only in B; and, for every shared species, its prey count, predator
  count and trophic level in each web.
- **Matching rule.** Species are matched by name, ignoring case and surrounding spaces. Links that touch a species
  the other web lacks are counted separately rather than treated as lost.
- **Export.** The per-species table and the link differences download as CSV.

### Changed — trait confidence and provenance

Every trait value now says where it came from and how sure EcoNeTool is about it. **Confidence labels
(high / medium / low) may change for species you looked up before**, usually downwards, because estimated values
are now scored instead of being counted as data. Trait tables exported from 1.6.x and 1.7.0 are comparable code
by code, but not label by label.

- **Each trait shows its source and how it was decided.** For every trait (size, feeding, mobility, position,
  protection, reproduction, temperature, salinity) the results table gives the database or rule that produced it,
  and the method: *observed* (a trait database or a measured size), *rule* (a taxonomic or depth rule, or the
  trait ontology), *ml* (machine-learning estimate), *phylo* (taken from close relatives) or *default* (no evidence:
  the cautious default code). The "imputation method" column summarises this, e.g. "ml+phylo".
- **One rule for the labels.** Every confidence is a number from 0 to 1; the label is low below 0.34, medium from
  0.34, high from 0.67. Some screens used 0.5 / 0.7 before. The overall confidence is the geometric mean of the
  five model traits.
- **Estimated values count as estimates.** Values filled from close relatives or by machine learning are now scored
  (relatives: vote strength x 0.55; machine learning: probability x 0.50) and lower the overall confidence. Before,
  relatives' values were not scored at all.
- **Offline database rows keep their own confidence.** A species found complete in the offline trait database was
  always labelled "high". It now carries the confidence stored for each trait, so most of these rows (BIOTIC,
  MAREDAT, PTDB) are "medium". Reproduction, temperature and salinity codes from the offline database are now used.
- **Body size on a class boundary.** A size exactly on a size-class boundary (e.g. a 50 cm fish) no longer drags the
  whole species to "low"; it keeps at least 30 % of its source's weight.
- **Which size wins.** When several databases give a size, the order is FishBase, SeaLifeBase, WoRMS, BIOTIC,
  MAREDAT, PTDB, BVOL, then the others. SeaLifeBase now beats WoRMS, and BIOTIC, MAREDAT and PTDB sizes are now
  used, so some invertebrate and plankton size classes (MS) change.
- **Protection with no evidence.** A species with no protection description and no taxonomic rule (for example a
  phytoplankton, mammal, bird or shark looked up online) is first offered to the machine-learning and relatives
  estimates; only if those fail does it get PR0, now labelled "Default" instead of "Taxonomy". The food web is
  unchanged for these species, but a default counts as weak evidence (0.30), so their overall confidence, and often
  their label, drops one band.
- **Partial lookups are retried sooner.** A lookup where WoRMS gave no classification, or where a database could not
  be reached (a timeout, a connection error or a server error), is marked "partial" in the results and is looked up
  again after one day instead of being kept for 30 days.
- **Phylogenetic estimates use real data only.** Close relatives vote only with observed or rule-based values,
  never with estimates or defaults, never with the species itself, and only when at least three relatives are
  available.
- **Custom harmonisation settings.** A session whose size thresholds or patterns differ from the defaults no longer
  receives offline-database codes made with the defaults; it looks the species up online.

### Notes

- No offline trait database rebuild is needed.
- Cached lookups (`cache/taxonomy/`) from 1.6.x are refreshed automatically on first use. Until the cache has
  refilled, fewer species have close relatives to estimate from.
- Machine-learning estimates of mobility (MB) stay off until the models are retrained on the new codes.
