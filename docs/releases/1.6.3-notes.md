### Changed — the SHARK tab works again

SHARK4R 1.2.0, the version installed on the server, removed every function the SHARK tab called, so the whole
tab was broken. It now uses the SHARK4R 1.2.0 functions.

- **Taxonomy:**
  - WoRMS lookups always work.
  - Dyntaxa and AlgaeBase are offered only when their API keys (`DYNTAXA_KEY`, `ALGAEBASE_KEY`) are set.
    Neither is set on the production server yet.
- **Environmental data and species records:**
  - Queries use a year range and a bounding box, and stop after 90 seconds.
  - The default query is a small Kattegat box for the previous complete year, and a notice under the button
    explains why. A SHARK query takes 25-90 seconds and pauses the app for every user while it runs.
  - The default year is worked out when each session starts, not once when the app starts.
- **Quality control:**
  - Validation uses SHARK4R's field checks for the chosen data type.
  - The "Outlier detection" and "Coordinate validation" checkboxes now run their checks. Before, they did
    nothing.
  - A failed validation, or a check that could not run, is shown as a problem instead of green "completed".
- **Errors:** a failed SHARK request shows a warning instead of crashing the tab or silently showing nothing.
- **Older SHARK4R:** with SHARK4R missing or older than 1.2.0, the tab shows installation help.

### Notes

- SHARK lookup cache files (`cache/shark/`) from 1.6.2 or earlier are no longer read; lookups are fetched again
  on first use. The old files can be deleted.
- No offline trait database rebuild is needed.
