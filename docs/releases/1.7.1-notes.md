# EcoNeTool 1.7.1 - Feedback Dashboard

Released 2026-10-19.

### Added — Feedback Dashboard

The **Feedback** sidebar entry (formerly "Feedback admin") is now a dashboard everyone can open, modelled on the
MarineSABRES SES Toolbox feedback management.

- **For everyone.** Seven counters (total reports, bug reports, suggestions, last 7 days, GitHub submitted, local
  only, resolved), an Open / Resolved / All filter, and a list of each report's date, type, title and status.
  Descriptions, steps and email addresses are not shown.
- **For admins.** The list adds the description, a GitHub link and a **Mark addressed** button per open report;
  a report can be closed as *addressed*, *won't fix* or *duplicate*, with a note and a fix reference (commit or
  PR). Clicking a row opens the full report. A **Duplicate Detection** tab compares reports by text similarity
  (adjustable threshold) and marks the newer report of a pair as a duplicate of the older one.
- **Who is an admin.** A session opened with `?admin=<FEEDBACK_ADMIN_KEY>` (unchanged), or a session unlocked with
  the admin password under Settings → API keys.

### Changed — Feedback form

- A **title** is now required. It is shown to other users in the Feedback list; the form says so.
- Bug reports have an optional **Steps to reproduce** field.
- New report type **General**, alongside Bug and Suggestion.
- A collapsible **System information** panel shows what is sent with the report (version, page, size of the
  loaded web, browser).
- One report per 30 seconds per session.

### Optional — GitHub issues

When `ECONETOOL_GITHUB_TOKEN` is set on the server (and optionally `ECONETOOL_GITHUB_REPO`, default
`razinkele/EcoNeTool`), each report is also filed as a GitHub issue and linked from the dashboard. The email
address is never included in the issue. Without the token nothing changes: reports are stored locally only.

### Upgrade notes

- The feedback database gains four columns (`title`, `steps`, `github_url`, `duplicate_of`). They are added
  automatically the first time the app opens the database; existing reports are kept and appear as "(untitled)".
- No offline trait database rebuild is needed.
